# Cranfield experiment results

Collection: Cranfield, 1400 documents, 225 queries. Generated by `scripts/run_experiments.py`.

## Conventions

- Cranfield qrels are **inverted** (raw 1 = complete answer, raw 4 = minimum interest, -1 = no judgement; see `cranqrel.readme` in the collection tarball). We map raw -> std with `5 - raw` for raw in 1..4 and -1 -> 0, so HIGHER is BETTER.
- Binary 'relevant' = std grade >= 2 (raw value in {1,2} = complete answer / high relevance); 1249 such judgements.
- Queries are natural-language sentences, so structured queries are DERIVED (datasets.derive_queries): Boolean AND = all content words; Phrase = every adjacent content-word bigram and trigram; NEAR/k = every adjacent content-word pair.
- A constrained system returns the UNION of its derived sub-query matches, ranked by BM25 inside that set. A query with an empty set scores AP=0 (honest low recall).

Reading: this is the honest headline result. BM25 keeps full recall and wins on MAP/nDCG, but the constrained systems **give up recall**: Phrase finds only 48% of the relevant documents that BM25's candidate pool contains, while raising precision *of the returned set* (set-precision 0.081 vs 0.010 for Boolean AND). High precision per hit, low recall overall.

Boolean AND is empty for 218/225 queries: Cranfield queries carry 10-19 content words and the abstracts average 174 tokens, so requiring EVERY content word almost never matches. It is included as the reference point, not as a contender.

## 1b. Proximity-bonus strength (Level 3C): lambda sweep

Score = BM25 + lambda * (pairwise proximity count, K=3). lambda=0 is plain BM25.

| 1.0000 | 0.2640 | 0.1924 | 0.2763 | 0.3460 |
| 2.0000 | 0.2622 | 0.1929 | 0.2739 | 0.3448 |


Honest reading: the proximity bonus changes MAP by less than a percent on these derived bag-of-content-words queries — the ranking is dominated by term statistics, not by term co-location. Phrase/proximity are better used as *filters* (which is how the constrained rows above are built) than as scoring features.

## 2. Effect of k (precision up / recall down as k shrinks)

| k | P@10 | set-recall | set-precision | MAP | avg #matches | empty queries |

| 1 | 0.1587 | 0.4817 | 0.0782 | 0.2160 | 87.3422 | 3/225 |
| 2 | 0.1644 | 0.5181 | 0.0700 | 0.2256 | 96.0400 | 1/225 |
| 3 | 0.1702 | 0.5471 | 0.0686 | 0.2308 | 100.8178 | 0/225 |
| 5 | 0.1729 | 0.5608 | 0.0637 | 0.2354 | 106.7422 | 0/225 |
| 10 | 0.1751 | 0.5869 | 0.0585 | 0.2393 | 116.7733 | 0/225 |
| 25 | 0.1756 | 0.6116 | 0.0484 | 0.2430 | 134.2844 | 0/225 |


The classic tradeoff shows up in the SET metrics: as k shrinks from 25 to 1, set-precision rises while set-recall falls — the returned set becomes purer and thinner. Note that ranked P@10 moves only slightly because every constrained system is ranked by BM25 *inside* its own candidate set, so a bigger k mostly adds recall without disturbing the top of the list.

Plot: `results/precision_recall_vs_k.png`.
